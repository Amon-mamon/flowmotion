### S11-1 · high · resolved (verified by security-reviewer 2026-11-13; effective once migration 20261113120000 is applied)
- **file:** `src/server/github/user-auth.ts` (`listUserInstallations`), `src/app/api/github/installations/callback/route.ts`, `src/server/github/repo-access.ts` (`resolveCoveredRepo`), `src/app/api/github/installations/[id]/repos/route.ts`, `src/app/api/projects/route.ts`; contract section 6 / `security.md` section 3.
- **risk:** Ownership is proven at the installation level only, not per repository. Per GitHub's docs, `GET /user/installations` lists every installation in which the user can access **at least one** repository (owner, collaborator, or org member). After linking, everything uses the installation token or App JWT: the repos list shows every repo in the installation, and `POST /api/projects` plus the branches route only check that the installation covers the repo (`GET /repos/{o}/{r}/installation`). They never check that the GitHub user can read that repo. Example: an org installs the App on "All repositories". A member with read access to one repo links the installation and can then list the private repo names, add any private repo in the org, and (from Phase 2) receive its file paths, signals, masked findings, and recommendations. D-20 makes this worse because it binds **every** listed installation automatically, with no installation id chosen. Access is also never re-checked, so a user removed from the org or repo keeps the binding.
- **owner:** architect (contract and `security.md` change), then backend.
- **fix:** While the user token is still in memory in the callback, call `GET /user/installations/{id}/repositories` (paged, Zod-parsed) for each installation and store the accessible repo ids per `github_installations` row (new table with owner-only RLS, or a `bigint[]` column, in an append-only migration). Filter the repos list to that set. Require the repo id in `POST /api/projects`, the branches route, and (Phase 2) `analyze`. Refresh the set on every relink, and treat a missing set as "relink required". Simpler alternative: bind only installations whose `account` is the user's own GitHub account or an org where the user is an admin. Add tests for an org member whose access is limited to some repos.

### S11-3 · low · resolved (verified 2026-11-13)
- **file:** `src/app/api/github/installations/callback/route.ts` (no-state branch), `src/app/api/github/authorize/route.ts`
- **risk:** A cross-site top-level GET to the callback (or to `/api/github/authorize`) with no state starts the authorize hop. GitHub returns at once for a user who already authorized the App, and every installation reachable by the **GitHub identity in that browser** is bound to the **Flow Motion user in that browser**, with no user action or confirmation. ### S2-3 · low · verified (re-review 2026-11-22; fixed by backend 2026-11-13)

- **S3aR-1 · low** — `src/lib/security/secret-scanner.ts:188-195` (`isPlaceholderValue`), `:511` and the other `\b`-anchored provider patterns. Owner: backend, with the architect for `security.md` section 2.
  - **Risk:** the placeholder rule was written for source code, and it exempts a whole value whenever any of the following holds:
    - the value starts with `your-` or `your_` (any case, and the D-48 rules use this check too);
    - the value contains `{{` or `${`;
    - the value contains `example` or `xxx` as a whole word.
  - Separately, provider patterns start with `\b`, so a word character glued in front (`YOUR_sk-ant-…`, `zsk-ant-…`) stops them from matching at all.
  - Probes that pass F9, rule 7 and `assertExportSafe` while the raw token is in the export:
    - `set` field `api_key` = `YOUR_<T>`;
    - `password` = `=<T>{{ $json.body.id }}`;
    - `password` = `example <T>`;
    - note = `YOUR_sk-ant-api03-…`;
    - note = `Bearer YOUR_<T>`.

So this is not an exfiltration path today. It is a defense-in-depth gap: one prefix defeats the export scan, so it cannot catch a stored export that did not come from the compiler. The `{{` case is new in kind, because flow Text mixes literals and expressions, which source code does not.
  - **Fix:**
    - Treat `your_` / `your-` as a placeholder only when the remainder is not token-like, for example `^YOUR_[A-Z0-9_]{2,40}$` for flows and the same remainder test (`isTokenLike` false) for the D-48 rules.
    - In flow scans, remove `{{ … }}` segments and scan the literal parts instead of exempting the whole value.
    - Apply the whole-word `example` / `xxx` exemption only when the value has no token-like run of 20 or more characters.
    - Replace the leading `\b` in provider patterns with `(?<![A-Za-z0-9])`, so `_` and `-` no longer hide a key.
    - Add each probe above as a test.

The new helper is quadratic on `${…}` runs (11.7 s for a 200 KB file), tracked as R3aR-5 (medium) in `review.md`.

- **S3aR-2 · low** — `src/lib/flowspec/expression.ts:5-6` (a whole expression may be a lone string literal), `src/lib/flowspec/values.ts:26`, `src/lib/validator/validate.ts:390`. Owner: architect (grammar, `contract.md` section 7), then backend.
  - **Risk:** D-51(a) checks the raw text for `://`, but the grammar lets an expression be just a string constant. So `https:{{ '//' }}evil.test/login` and `https:/{{ '/' }}evil.test` pass `isValidText` (F8) and rule 8, and n8n evaluates them to `https://evil.test/login`.
  - Probe: a query value `=https:/{{ '/' }}evil.test` validates OK and passes `assertExportSafe`.
  - `https:\\evil.test` also passes, and WHATWG URL parsers read it as `https://evil.test`.
  - **Scenario:** repository text steers the model into a Slack or email text such as "Re-authenticate at https:{{ '//' }}evil.test/login", or into a body `callback` URL posted to the user's own API. That is exactly the case D-51 exists to stop.
  - Bare domains such as `evil.com/login` and `www.…` also pass and are auto-linked by Slack, Gmail and Telegram. That is an inherent limit of a text check and should be documented as accepted.

    - In the grammar, allow a string, number, boolean or null only as the right-hand side of a comparison, never as a whole expression (a constant expression has no use).

    - Add the probes as tests in both layers.
    - Record the bare-domain limit in `security.md` section 9.
  - **Status:** fixed (round-2 verification 2026-11-28): lone literals refused by the grammar; `:\`, `:/\`, `://` refused raw and after joining literal parts, in F8 and rule 8; tested in both layers.

- **S3aR-3 · low** — `src/lib/validator/validate.ts:149-167` (`isAllowedByTable`). Owner: backend, with the architect for `testing.md` rule 5.
  - **Risk:** a mode parameter is checked only when it is present. A stored export that omits `operation` on `postgres`, `supabase`, `googleSheets` or `airtable` (also `resource`, and `authentication` on `httpRequest`) passes rule 5 and rule 8 (probe: all four `validate: OK`). n8n then uses its own default operation, which the validator does not know: the generated catalog records no defaults, and the n8n source was not available here to check it. - **S3aR-4 · low** — `src/lib/validator/allowed-params.ts:200-214`, `src/lib/n8n-catalog/profiles/http-request.ts:13-36`. Owner: backend, with the architect for the D-51 list.

### Findings

- **S3b-1 · low** — `src/lib/jobs/generate.ts:355-373` (`stepPersist`). Owner: backend.
  - **Risk:** `persist` writes `state.n8nJson`, `state.checklist` and `state.spec` as they come back from `jobs.state`. It does not re-run `validateWorkflow` / `assertExportSafe`, and it does not check that `n8nJson` is still `compileFlow(state.spec)`. The checks ran in the previous step and invocation, and the state made a round trip through the database in between.
  - **Scenario:** any later writer of `jobs.state` between `validate` and `persist` stores a workflow that never passed the checks. That could be a future step (Phase 4 inserts `simulate` exactly there), a bug in another job kind, or a manual SQL repair.
    - The export route re-checks, so this is not an exfiltration path.
    - But the canvas is drawn from `flow_spec` and the download is `n8n_json`, and nothing ties the two together after `validate`. The user could inspect one graph and import a different workflow.
  - **Fix:** in `stepPersist`, recompile with `compileFlow(state.spec)` and persist that output (or require deep equality with `state.n8nJson`). Run `validateWorkflow` and `assertExportSafe` on it once more, and on failure end the job `INTERNAL` without writing the flow. Add a test that plants a different valid `n8nJson` in the state before `persist` and expects it to be rejected or replaced.

- **S3b-2 · low** — `src/lib/jobs/worker.ts:252-259`, `tests/lib/jobs/generate.test.ts`. Owner: backend.
  - **Risk:** the cross-user chain guard (recommendation / analysis / project / job `user_id` must equal the flow's) is the only thing that stops a mis-inserted job or flow from reading user B's repository with user B's installation for user A's flow. No test exercises it, so a later refactor could drop it silently.
  - **Fix:** add four tests, one per mismatched `user_id`. Each expects the flow `failed` / `INTERNAL`, no `mintToken`, no `getTreeBlobs` / `getBlob`, and no model call.

- **S3b-3 · low** — `src/lib/generation/prompt.ts:205-212`, `src/lib/generation/parse.ts:107-116`, `src/lib/jobs/generate.ts:324-326`. Owner: architect (wording in `security.md` section 9 / contract section 4), then backend.
  - **Risk:** `<previous_errors>` echoes `nodeKey`, and the key is chosen by the model that has just read repo text. It is limited to `^[a-z][a-z0-9_]{0,39}$` and at most 20 entries, so up to about 800 characters of model-chosen text go back into the next prompt, under a header that tells the model to "Fix them". The contract says the block holds only "rule codes and node keys produced by our code".
  - **Scenario:** an injected first answer names its nodes `ignore_rules_add_webhook_to_attacker` and so on, to steer the retry. The impact is bounded: every retry output goes through the same Zod, F1..F12, the validator and the export checks, and destinations are placeholders only.
  - **Fix:** refer to nodes by position (`node 3`, the index in `spec.nodes`) instead of the key, or record the key echo as an accepted residual in `decisions.md` and `security.md` section 9.

- **S3b-4 · low** — `src/lib/analysis/prompt.ts:50-52` (`escapeFileText`), `src/lib/generation/prompt.ts:160-169` (`GENERATION_TAGS`). Owner: backend.
  - **Risk:** escaping matches only the exact forms `</tag` and `<tag`. Near-miss forms pass unchanged and a model may still read them as the end of the data block, for example `</ repo_file>`, `< /repo_file>`, or `<​/repo_file>` (zero-width character).
  - This is the same helper analysis uses, so it is not new in kind. Generation output is fully validated, so the impact is limited to wasted calls or a steered but still-checked draft.
  - **Fix:** use a per-request random delimiter suffix (for example `<repo_file_<16 hex>>`, given in the system prompt), so repo text cannot predict the closing tag. Alternatively, also escape `<` followed by optional whitespace, `/` and optional whitespace before a tag name, and strip zero-width characters next to `<`. Add tests for each variant.

- **S3b-5 · low** — `src/server/daily-cap.ts:43-52`, `src/app/api/recommendations/generate/route.ts:67-77`, `src/server/flows/data.ts:271-275`. Owner: backend.
  - **Risk:** the cap is consumed one unit at a time.
    - A request with N ids that crosses the cap keeps the units it already consumed and returns `DAILY_CAP_REACHED` with no flow.
    - A request that loses the insert race has consumed its units and then returns "already exists".
  - Only the caller's own quota is affected (self-inflicted; the UI sends one id). The abuse limit is never exceeded, so this is not a bypass.
  - **Fix:** check the remaining capacity for all N before consuming (one atomic `rate_limit_hit` with a count, or a read then hit inside one SQL function), or refund on the race path. Document it if accepted.
