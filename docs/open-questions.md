# Open questions

Each has a recommended default so work can continue. The architect resolves them with the owner and records answers in `decisions.md`.

- **OQ-1** "Motion" 3D scrolling: use Motion scroll with CSS 3D transforms, or Three.js? Default: Motion plus CSS 3D, no Three.js.
- **OQ-2** Text on light-red buttons: black (readable) or white (as requested)? Default: black on red, white everywhere else.
- **OQ-3** AI provider and model for analysis and generation. Default: Anthropic API, model name in `ANALYSIS_MODEL`.
- **OQ-4** ~~Background jobs: Supabase Edge Function worker with a DB queue, or another Supabase-only approach?~~ **Resolved 2026-11-10 → D-10** (chunked `jobs` state machine, `contract.md` sections 4 and 5).
- **OQ-5** License impact of depending on n8n packages to generate the catalog and of running a pinned n8n for the dev/CI import test (D-9). Default: dev-time extraction only, commit the generated JSON, no runtime n8n dependency, dev/CI import test is internal only. **Owner must confirm with n8n before public launch.**
- **OQ-6** Credential placeholder format and top-level fields in exported n8n JSON. Default: omit credential ids, list credentials in the checklist, mark exports "unverified import" until tested (`n8n.md`).
- **OQ-7** Which n8n version to pin. Default: latest stable at the start of Phase 3.
- **OQ-8** Private repositories: allowed through the GitHub App for selected repos only? Default: yes, with a clear privacy notice.
- **OQ-9** Monorepos. Default: analyze the whole repo within file caps, one project per repo.
- **OQ-10** Payment provider and countries (NOT READY, see `subscription.md`).
- **OQ-11** Analytics and error-monitoring provider for Phase 5. Default: none in v1; log errors (ids, counts, error codes only, no repo text) to Supabase. Revisit before launch. Any new dependency needs a `docs/requests.md` entry first.
- **OQ-12** AI provider data retention. Default: Anthropic API with zero-retention terms; the owner must confirm the retention terms in writing before launch, and the `/privacy` page must match what is confirmed.
- **OQ-13** [2026-11-10] When generation's 3 model calls are used up and the validator passed but the mock test still fails: mark the flow `failed`, or keep it `ready` at level Valid with the failures shown? Default (applied in `contract.md` section 4 and `testing.md`): `ready` at Valid with the failing run visible; `failed` with `GENERATION_EXHAUSTED` only when the validator never passed. Reason: a Valid export is still useful and `testing.md` says failures are never hidden.
- **OQ-14** [2026-11-10] Account deletion ("delete all my data" beyond per-project delete). Default: not in v1 scope; per-project delete cascades everything (`contract.md` section 5); add a "Delete account" action in `/settings` in Phase 5 only if the owner asks.
- **OQ-15** [2026-11-10] Sign-in method. Default: Supabase Auth email + password only (no social login); the GitHub App installation is separate from sign-in. "Continue with GitHub" can be added later through the Supabase GitHub provider without code changes to the GitHub App flow.
- **OQ-16** [2026-11-10] How the job worker (Supabase Edge Function, Deno, D-10) shares code with `src/lib/**`. Default (applied in `contract.md` section 9): a Deno import map pointing at `src/lib` and `src/schemas`, which must stay runtime-neutral (no `next/*`, no Node-only APIs). Fallback if the import map proves unworkable in Phase 2: move the worker to a Next.js route `POST /api/internal/worker` guarded by the service-role bearer, keeping the same `jobs` state machine and cron/pg_net trigger; that would need a `WORKER_SECRET` env name and a hosting plan whose function timeout covers the 60 s model step. Backend decides in Phase 2 and the architect records the result.
- **OQ-17** [2026-11-10] Hosting for the Next.js app (affects function timeouts and the `APP_URL`). Default: Vercel, Node runtime for route handlers; no route handler does long work (all long work is in the worker).
- **OQ-18** [2026-11-10, backend; renumbered from a duplicate OQ-13 by the architect] Next.js 16 renamed `middleware.ts` to `proxy.ts` (`export function proxy`). Contract section 3 and AGENTS.md say `src/middleware.ts`. Default (applied in `contract.md` sections 3 and 9; AGENTS.md ownership table still needs the owner to change `src/middleware.ts` to `src/proxy.ts`): implement it as `src/proxy.ts` in Phase 1 (backend-owned, same role). Also: create-next-app 16 enables `cacheComponents` by default; Phase 0 left it off because every cookie/session read would then need a Suspense boundary. Default: keep it off for v1. shadcn v4 `init -d` uses the "base-nova" preset (Base UI primitives, `cn` from the `cn` package); the frontend should add components with `npx shadcn@latest add <name>` and not change the preset without a request.
