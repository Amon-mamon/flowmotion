# Design — Flow Motion

Modern, bold, calm. **Not glassmorphism:** no backdrop blur, no translucent panels, no frosted cards. Solid surfaces with 1 px borders.

## Palette (only these)
| Token | Value | Use |
|---|---|---|
| `--background` | `#0A0A0A` | page background |
| `--surface` | `#141414` | cards, panels |
| `--surface-2` | `#1C1C1C` | hover, inputs |
| `--border` | `#2A2A2A` | borders |
| `--accent` | `#FF6B6B` (light red) | buttons, links, active states, edges |
| `--accent-strong` | `#FF8A8A` | hover |
| `--foreground` | `#FFFFFF` | text on dark surfaces |
| `--muted` | `#A3A3A3` | secondary text |
**Recommendation risk tokens (D-36, the only exception to the hue rule; used only by the recommendation risk badge):**
| Token | Value | Use |
|---|---|---|
| `--risk-low` | `#4ADE80` (green) | "Low risk" badge border, icon, text |
| `--risk-medium` | `#FBBF24` (amber) | "Medium risk" badge border, icon, text |
| `--risk-high` | `#FF6B6B` (red, same value as `--accent`) | "High risk" badge border, icon, text |

Only light red, black, and white (plus these neutral greys for depth, and the three risk tokens above on the risk badge only). No other hues. Status uses shape and text, not extra colors: icon plus label for success, warning, error. Severity badges use outlined red styles with different icons and text.
**Contrast:** white on `#FF6B6B` is too low for small text. Buttons filled with the accent use **black text**. White text goes on black and dark surfaces. (Confirm with the owner: OQ-2.)

## Type and layout
- One clean sans family (for example Geist or Inter) plus a mono family for code and JSON. Large confident headings, generous spacing.
- 8 px spacing grid, 12 px radius on cards, 8 px on controls.
- Use shadcn/ui components themed through CSS variables. Do not hardcode colors in components.

Hero (clear promise, one primary button "Get started" → `/signup`) · how it works as a scroll story · feature highlights (repo scan, node flows, simulation, n8n export) · security section · "Plans coming soon" (no prices, no checkout, no button; subscription is NOT READY) · FAQ · footer with links to `/privacy` and `/terms` (plain static pages, same tokens, no animation). Header: wordmark, "Log in" (`/login`), "Sign up" (`/signup`).
**Exact "Plans coming soon" copy (do not change without the architect):** heading "Plans coming soon"; body "Flow Motion is in early testing. There are no paid plans, prices, or credits yet. Pricing will be announced here before anything changes." Nothing else in that section.
**Scroll animation:** Motion `useScroll` and `useTransform` with CSS perspective and 3D transforms (tilting, depth, stacking cards). Respect `prefers-reduced-motion` (replace with fades). No Three.js unless the owner asks (OQ-1). Keep it smooth on mobile.

## App
- Shell: left sidebar with wordmark, "Dashboard" (`/dashboard`), "Settings" (`/settings`), and at the bottom the user's display name or email with "Sign out"; collapses to a sheet on small screens.
- Dashboard: projects grid (card: repo full name, chosen branch `project.branch` in the mono font with a git-branch icon, status badge, created date; links to the project page; Phase 1.1), "Add repository" button opening the two-step dialog below, recent flows (empty state "No flows yet" until Phase 3). After the GitHub callback: `?connected=1` → notice "GitHub connected", `?error=github` → notice "Could not connect GitHub. Try again.", `?error=github_none` → notice "Flow Motion is not installed on any GitHub account you can access. Install it first." with the "Connect GitHub" link.
  - **Phase 1.1 security fixes (D-22, D-23):** `?connected=1` → "GitHub connected as @<githubUserLogin>" (login from the installations query, first non-null; plain "GitHub connected" when none). `?link=github` → notice "Flow Motion was installed or updated on GitHub. Link it to your account to continue." with the button "Link existing installation" (`/api/github/authorize`). `?error=github_account` → notice "You are signed in to GitHub with a different account than the one linked to Flow Motion. Switch accounts on GitHub, or disconnect the linked installations in Settings first." with a "Settings" link.
  - **Refresh repository access (D-22):** the action is always the text "Refresh repository access", a plain anchor to `/api/github/authorize`. Whenever an API call returns `GITHUB_REFRESH_REQUIRED`, show the plain notice "Flow Motion needs to re-check which repositories you can access on GitHub. This happens at least once a day." followed by that action. Surfaces: the Add repository dialog (in place of the repo list when the repos list returns it; inline under the branch list or above the buttons when branches or `POST /api/projects` return it) and the project page (after Analyze). No error styling beyond the plain notice.
  - **Empty states (Phase 1.1 fix):** no installations (`GET /api/github/installations` returns none) → heading "No projects yet", body "Connect GitHub to choose a repository.", primary "Connect GitHub" (`/api/github/install`) and below it the text link "Already installed Flow Motion on GitHub? Link existing installation" (`/api/github/authorize`). At least one installation but no projects → heading "No projects yet", body "Add a repository to analyze it.", primary "Add repository" (opens the dialog). Never show "Connect GitHub" as the main action when an installation exists. While installations are loading, show the skeleton, not either empty state.
- **Add repository dialog (Phase 1.1), two steps, one dialog:**
  - Step 1 title "Choose a repository": installation select, repo list with "Load more" (unchanged), footer link "Link existing installation" (`/api/github/authorize`) and, below it, "Missing a repository? Refresh repository access" (only the last three words are the link, `/api/github/authorize`; Phase 1.1 security fixes). Selecting a repo enables "Next".
  - Step 2 title "Choose a branch", description "Flow Motion analyzes the latest commit on this branch. To use a different branch later, add the repository again." Above the list the selected repo full name. Filter input with label "Search branches" and placeholder "Filter loaded branches" (filters only branches already loaded, case-insensitive substring). List of single-select rows (radio semantics, keyboard navigable): branch name in mono; the default branch is pinned first, preselected, and carries an outlined "default" badge (pinned even before it appears in a loaded page; never listed twice); protected branches show a lock icon plus the text "Protected". "Load more branches" button while `hasMore`. Filter with no match: "No loaded branch matches. Load more branches or check the name." Loading: row skeletons. Load error: "Could not load branches. Try again." with a "Retry" button.
  - Buttons: "Back" (to step 1, keeps the repo selection) and primary "Add repository" (black text on accent; disabled until a branch is selected; shows "Adding…" while pending). `VALIDATION_ERROR` messages from `POST /api/projects` ("That branch was not found.", "This repository and branch are already connected", coverage message) are shown inline in the dialog as plain text; `RATE_LIMITED` uses the shared copy. On success close the dialog and navigate to the new project page.
- Auth pages: one centered card (`--surface`), form fields with labels, primary button with black text on the accent, link to the other page ("Already have an account? Log in" / "No account? Sign up"). **Signup rate limit (Phase 1.1 fix):** when Supabase returns the email rate-limit error (error code `over_email_send_rate_limit`, or HTTP 429 from `signUp`), show "Too many sign-up emails were sent recently. Wait a few minutes and try again." instead of the generic error; any other signup error keeps the generic message. This copy is confirmed exactly (D-23, R11-1). **Login rate limit (D-23, R11-4):** when sign-in returns `over_request_rate_limit` or HTTP 429, show "Too many attempts. Please wait a moment and try again."; every other sign-in error keeps "Invalid email or password".
- Project page (`/projects/[projectId]`): header with repo full name, "Branch" label plus `project.branch` in mono (followed by an outlined "default" badge when it equals `defaultBranch`), validity badge, Analyze button (or "View progress" while an analysis is active), notices, and the analyses history (status label, recommendation count text, short commit SHA, started date, link to each analysis). **Recommendation count text (Phase 2d, D-36)**, shown after the status label as "· <text>" from `recommendationCount`: ≥ 2 → "<N> recommendations" (for example "8 recommendations"); 1 → "1 recommendation"; 0 → "No recommendations"; `null` with `errorCode = AI_DISABLED` → "AI analysis not enabled"; `null` with `errorCode = AI_UNAVAILABLE` → "AI service did not respond"; any other `null` (active, `rejected`, other failures) → no text and no separator. A `DAILY_CAP_REACHED` error is shown as a plain notice with the reset time, never as a plan or upgrade prompt.
- Analysis page (`/projects/[projectId]/analysis/[analysisId]`), top to bottom: header line "Branch `<branch>` at `<first 7 of commitSha>`" (SHA part omitted while null), progress (while active), validation result, "Files" summary, security findings, detected signals, recommendations.
  - Files summary: read count plus "Skipped" grouped by reason with these labels: "Blocked for safety" (denied), "Unsupported file type" (extension), "Too large (over 200 KB)" (size), "Over the 400-file limit" (cap), "Not sent to AI (size budget)" (budget, hidden when 0). Explanation sentence under it: "Flow Motion never opens files that might hold secrets. Some ordinary files with names like "secret" or "credentials" are skipped too."
  - Findings: one row per finding with a severity badge (outlined, icon plus "High" / "Medium" / "Low"), category label (snake_case turned into words, for example "Hardcoded secret"), `filePath:line` (path only when line is null), masked evidence in the mono font, remediation sentence. Empty state "No secrets found in the files we read."
  - Signals: grouped by kind with headings "Routes", "Webhooks", "Schedules", "Queue consumers", "Messaging", "Database writes", "CI workflows", "Environment variables"; each item shows the label and file path. Empty state "No automation signals found."
  - Recommendations: section heading "Recommendations". **Count line (Phase 2d, D-36)** directly under the heading, muted text, only for a `done` analysis with `errorCode` null once the list has loaded: "<N> recommendations found" for N ≥ 2 (for example "8 recommendations found"), "1 recommendation found" for N = 1; N = 0 shows no count line, only the empty state "No automations found". N is the length of the loaded list. No count line while the list loads, for `done` with `AI_DISABLED` (the AI notice in "Status to UI mapping" replaces the list), or on `failed` (including `AI_UNAVAILABLE` and `MODEL_OUTPUT_INVALID`), `rejected`, or active analyses. Then selectable cards (checkbox, title, trigger type, confidence as a percentage, required credentials, risk badge, rationale). **Risk badge (D-36):** outlined (1 px border, icon, and text in the risk token, transparent background, 8 px radius), text "Low risk" (`--risk-low`), "Medium risk" (`--risk-medium`), "High risk" (`--risk-high`); never the finding severity badge. At most 8 cards per analysis (older analyses may show more). Generate button below the list; in Phase 2 it is disabled with the hint "Flow generation arrives in the next phase".
  - All repo-derived text (paths, labels, evidence, model text) is rendered as plain text.
- Flow page: React Flow canvas (dark, grid dots, accent edges), node cards with icon and label, click a node to open an inspector drawer showing type, parameters (read-only in v1), required credential, source file, and notes. Right-hand or bottom test panel (see `testing.md`). Export button with the setup checklist and, when `importVerified` is false, the plain notice "Import into n8n x.y not yet verified".
- Settings page: display name form, connected GitHub installations (account login, connected date, "Linked as @<githubUserLogin>" when not null, and when `needsRefresh` an outlined badge "Needs refresh" plus the "Refresh repository access" link; Phase 1.1 security fixes) with a Disconnect action (confirm dialog, explains that projects keep their results but need a reconnect to analyze) and a "Manage on GitHub" link, plus under the list the links "Connect another account" (`/api/github/install`) and "Link existing installation" (`/api/github/authorize`), nothing about plans.
- Every list has loading, empty, and error states.

**Status to UI mapping** (enums from `contract.md` section 5):
- Project `pending` → "Not analyzed yet" with Analyze button; `valid` → validity badge with kind (website / app); `invalid` → outlined badge plus `invalid_reason`, Analyze still offered; `stale = true` → notice "New commits since the last analysis" with Re-analyze; `installation_id = null` → notice "Reconnect GitHub to analyze".
- Analysis `queued` / `validating` / `scanning` / `analyzing` → progress bar with labels "Queued", "Checking project", "Scanning files", "Analyzing", polling; `done` → counts, findings, signals, recommendations (empty state "No automations found" when there are none); `done` with `errorCode = AI_DISABLED` → counts, findings, and signals as usual, and in place of recommendations the plain notice "AI analysis is not enabled yet. Security findings and detected signals are shown above. Recommendations will appear here once AI analysis is turned on." (no error styling, no button); `rejected` → the validation reason, no findings or recommendations; `failed` → error state with a Retry (Analyze) button and the message per `errorCode`: `GITHUB_ACCESS_LOST` "Flow Motion can no longer read this repository. Reconnect GitHub and try again."; `BRANCH_NOT_FOUND` "The branch <branch> no longer exists on GitHub. Add the repository again and choose another branch." (no Retry button, since re-analyzing would fail the same way; link "Back to dashboard"); `MODEL_OUTPUT_INVALID` "The AI returned an answer we could not use. Your security findings are saved below. Try analyzing again." (findings and signals still shown); `JOB_EXPIRED` (Phase 2 review fixes, D-29) "This analysis stopped making progress and was cancelled. Try again." (Retry shown); `AI_UNAVAILABLE` (Phase 2c, D-35) "The AI service did not respond. Your security findings and detected signals are saved below. Try again later." (Retry shown; never names the provider); `INTERNAL` or anything else "Something went wrong during analysis. Try again." On every `failed` analysis whose `progress` is at least 70 (`detect` finished), the saved findings and signals are shown below the message (R2-4).
- Recommendation `new` → selectable card; `selected` → card disabled with "Generating"; `generated` → card with a link to the flow.
- Flow `generating` → skeleton canvas with "Generating" and polling; `ready` → canvas, inspector, test panel, export; `failed` → error state ("Could not generate a valid flow after 3 attempts" for `GENERATION_EXHAUSTED`) with a link back to the project.
- Test run `level = valid` → badge "Valid" (plus the failing cases if `passed = false`); `level = simulated` → badge "Simulated" with the required wording from `testing.md`.
- `DAILY_CAP_REACHED` → plain notice "Daily limit reached (10 analyses per day). It resets at 00:00 UTC." (for generation: "30 flows per day"); `PROJECT_STALE_ANALYSIS` → dialog with "Generate anyway" and "Re-analyze"; `RATE_LIMITED` → "Too many requests, try again in a minute".

## Accessibility
Visible focus rings (accent), full keyboard navigation including the canvas where possible, labels on all form fields (react-hook-form + Zod messages), sufficient contrast, reduced motion support, semantic headings.

## Tone
Direct and honest. Never overpromise: say "Simulated with mock data", not "guaranteed to work".
