# Design — Flow Motion

Modern, bold, calm. **Not glassmorphism:** no backdrop blur, no translucent panels, no frosted cards. Solid surfaces with 1 px borders.

## Palette (only these)
| Token | Value | Use |
|---|---|---|
| `--background` | `#0A0A0A` | page background |
| `--surface` | `#141414` | cards, panels |
| `--surface-2` | `#1C1C1C` | hover, inputs |
| `--border` | `#2A2A2A` | borders |
| `--accent` | `#FF6B6B` (light red) | buttons, links, active states, edges |
| `--accent-strong` | `#FF8A8A` | hover |
| `--foreground` | `#FFFFFF` | text on dark surfaces |
| `--muted` | `#A3A3A3` | secondary text |
**Recommendation risk tokens (D-36, the only exception to the hue rule; used only by the recommendation risk badge):**
| Token | Value | Use |
|---|---|---|
| `--risk-low` | `#4ADE80` (green) | "Low risk" badge border, icon, text |
| `--risk-medium` | `#FBBF24` (amber) | "Medium risk" badge border, icon, text |
| `--risk-high` | `#FF6B6B` (red, same value as `--accent`) | "High risk" badge border, icon, text |

Only light red, black, and white (plus these neutral greys for depth, and the three risk tokens above on the risk badge only). No other hues. Status uses shape and text, not extra colors: icon plus label for success, warning, error. Severity badges use outlined red styles with different icons and text.
**Contrast:** white on `#FF6B6B` is too low for small text. Buttons filled with the accent use **black text**. White text goes on black and dark surfaces. (Confirm with the owner: OQ-2.)

## Type and layout
- One clean sans family (for example Geist or Inter) plus a mono family for code and JSON. Large confident headings, generous spacing.
- 8 px spacing grid, 12 px radius on cards, 8 px on controls.
- Use shadcn/ui components themed through CSS variables. Do not hardcode colors in components.

## Landing page (`/`)
Hero (clear promise, one primary button "Get started" → `/signup`) · how it works as a scroll story · feature highlights (repo scan, node flows, simulation, n8n export) · security section · "Plans coming soon" (no prices, no checkout, no button; subscription is NOT READY) · FAQ · footer with links to `/privacy` and `/terms` (plain static pages, same tokens, no animation). Header: wordmark, "Log in" (`/login`), "Sign up" (`/signup`).
**Exact "Plans coming soon" copy (do not change without the architect):** heading "Plans coming soon"; body "Flow Motion is in early testing. There are no paid plans, prices, or credits yet. Pricing will be announced here before anything changes." Nothing else in that section.
**Scroll animation:** Motion `useScroll` and `useTransform` with CSS perspective and 3D transforms (tilting, depth, stacking cards). Respect `prefers-reduced-motion` (replace with fades). No Three.js unless the owner asks (OQ-1). Keep it smooth on mobile.

  - Step 2 title "Choose a branch", description "Flow Motion analyzes the latest commit on this branch. To use a different branch later, add the repository again." List of single-select rows (radio semantics, keyboard navigable): branch name in mono; the default branch is pinned first, preselected, and carries an outlined "default" badge (pinned even before it appears in a loaded page; never listed twice); protected branches show a lock icon plus the text "Protected". - Auth pages: one centered card (`--surface`), form fields with labels, primary button with black text on the accent, link to the other page ("Already have an account? Log in" / "No account? Sign up"). **Signup rate limit (Phase 1.1 fix):** when Supabase returns the email rate-limit error (error code `over_email_send_rate_limit`, or HTTP 429 from `signUp`), show "Too many sign-up emails were sent recently. - Project page (`/projects/[projectId]`): header with repo full name, "Branch" label plus `project.branch` in mono (followed by an outlined "default" badge when it equals `defaultBranch`), validity badge, Analyze button (or "View progress" while an analysis is active), notices, and the analyses history (status label, recommendation count text, short commit SHA, started date, link to each analysis). **Recommendation count text (Phase 2d, D-36)**, shown after the status label as "· <text>" from `recommendationCount`: ≥ 2 → "<N> recommendations" (for example "8 recommendations"); 1 → "1 recommendation"; 0 → "No recommendations"; `null` with `errorCode = AI_DISABLED` → "AI analysis not enabled"; `null` with `errorCode = AI_UNAVAILABLE` → "AI service did not respond"; any other `null` (active, `rejected`, other failures) → no text and no separator. A `DAILY_CAP_REACHED` error is shown as a plain notice with the reset time, never as a plan or upgrade prompt.
- Analysis page (`/projects/[projectId]/analysis/[analysisId]`), top to bottom: header line "Branch `<branch>` at `<first 7 of commitSha>`" (SHA part omitted while null), progress (while active), validation result, "Files" summary, security findings, detected signals, recommendations.
  - Files summary: read count plus "Skipped" grouped by reason with these labels: "Blocked for safety" (denied), "Unsupported file type" (extension), "Too large (over 200 KB)" (size), "Over the 400-file limit" (cap), "Not sent to AI (size budget)" (budget, hidden when 0). Explanation sentence under it: "Flow Motion never opens files that might hold secrets. Some ordinary files with names like "secret" or "credentials" are skipped too."
  - Findings: one row per finding with a severity badge (outlined, icon plus "High" / "Medium" / "Low"), category label (snake_case turned into words, for example "Hardcoded secret"), `filePath:line` (path only when line is null), masked evidence in the mono font, remediation sentence. Empty state "No secrets found in the files we read."
  - Signals: grouped by kind with headings "Routes", "Webhooks", "Schedules", "Queue consumers", "Messaging", "Database writes", "CI workflows", "Environment variables"; each item shows the label and file path. Empty state "No automation signals found."
  - Recommendations: section heading "Recommendations". **Count line (Phase 2d, D-36)** directly under the heading, muted text, only for a `done` analysis with `errorCode` null once the list has loaded: "<N> recommendations found" for N ≥ 2 (for example "8 recommendations found"), "1 recommendation found" for N = 1; N = 0 shows no count line, only the empty state "No automations found". N is the length of the loaded list. No count line while the list loads, for `done` with `AI_DISABLED` (the AI notice in "Status to UI mapping" replaces the list), or on `failed` (including `AI_UNAVAILABLE` and `MODEL_OUTPUT_INVALID`), `rejected`, or active analyses. Then one card per recommendation (title, description, trigger type, confidence as a percentage, required credentials, source files, risk badge, rationale, and the action area below). **No checkbox, no selected state, no "N selected" bar (Phase 3a, D-42):** owner testing showed every card as checked, and each flow is started on its own. **Risk badge (D-36):** outlined (1 px border, icon, and text in the risk token, transparent background, 8 px radius), text "Low risk" (`--risk-low`), "Medium risk" (`--risk-medium`), "High risk" (`--risk-high`); never the finding severity badge. At most 8 cards per analysis (older analyses may show more).
  - **Card action area (Phase 3, D-42; bottom of each card, exact copy), by `status` and `flowId`:**
    - `new`, `flowId` null → primary button "Generate flow" (black text on accent). While the request is pending: "Starting…", disabled.
    - `new`, `flowId` set (the last attempt failed) → muted text "The last attempt did not produce a flow." with the link "View details" (`/flows/<flowId>`), and the primary button "Try again" (same action as "Generate flow").

  - On success the app goes to `/flows/<flowId>`. It resets at 00:00 UTC."; `GITHUB_REFRESH_REQUIRED` → the shared refresh notice and action; `RATE_LIMITED` → the shared copy; anything else → "Could not start generation. Try again."
  - `PROJECT_STALE_ANALYSIS` → dialog, title "This analysis is out of date", body "New commits were pushed after this analysis.   - All repo-derived text (paths, labels, evidence, model text) is rendered as plain text.
- **Flow page (`/flows/[flowId]`, Phase 3a; exact copy):**
  - Header: link "Back to analysis" (`/projects/<projectId>/analysis/<analysisId>`), the flow name as the page heading, the description as muted text, the repo full name in mono. When `ready`: the level badge "Valid" (outlined, check icon) with the sentence "Passed Flow Motion's structure checks.   - `generating`: skeleton canvas, text "Generating your flow. This usually takes less than two minutes.", polling every 2 s. No export panel.
  - `failed`: error state with the message by `errorCode` and the link "Back to analysis" (the user retries from the recommendation card): `GENERATION_EXHAUSTED` "Could not generate a valid flow after 3 attempts."; `AI_UNAVAILABLE` "The AI service did not respond.   - **Canvas** (`ready`): React Flow (`@xyflow/react`), dark background with grid dots, accent edges with arrowheads, read-only (pan, zoom, and select only; no dragging nodes, connecting, or deleting), fitted to view on load, zoom controls, no minimap. Positions come from the API. Node card (`--surface`, 1 px border, 12 px radius): an icon for the node type, the label, and under it the short type name in muted mono (for example `slack`); the trigger node carries an outlined "Trigger" tag; a node that needs a credential shows a key icon. The selected node has an accent border. Edges leaving a node with more than one output show that output's label ("true" / "false", "done" / "loop", the switch case value, "fallback"). Nodes are focusable in graph order; Enter or Space opens the inspector.
  - **Node inspector**: a drawer (right side; bottom sheet on small screens) titled with the node label, closed with Esc or the close button. Rows in this order: "Type" (short name, full type in mono below); "Parameters" (read-only key and value tree in mono; empty → "No parameters"); "Credential" ("Needs a <name> credential in n8n" or "No credential needed"); "Source files" (mono list, or "None"); "Notes" (omitted when null). - Settings page: display name form, connected GitHub installations (account login, connected date, "Linked as @<githubUserLogin>" when not null, and when `needsRefresh` an outlined badge "Needs refresh" plus the "Refresh repository access" link; Phase 1.1 security fixes) with a Disconnect action (confirm dialog, explains that projects keep their results but need a reconnect to analyze) and a "Manage on GitHub" link, plus under the list the links "Connect another account" (`/api/github/install`) and "Link existing installation" (`/api/github/authorize`), nothing about plans.
- Every list has loading, empty, and error states.

**Status to UI mapping** (enums from `contract.md` section 5):
- Project `pending` → "Not analyzed yet" with Analyze button; `valid` → validity badge with kind (website / app); `invalid` → outlined badge plus `invalid_reason`, Analyze still offered; `stale = true` → notice "New commits since the last analysis" with Re-analyze; `installation_id = null` → notice "Reconnect GitHub to analyze" followed by the sentence (Phase 1.2, D-45) "If this repository is on someone else's personal GitHub account, Flow Motion can no longer analyze it. Its past results stay here until you delete the project."; on the dashboard project card the muted line "Not connected to GitHub" with an unplug icon (Phase 1.2). Such projects are never hidden.
- Analysis `queued` / `validating` / `scanning` / `analyzing` → progress bar with labels "Queued", "Checking project", "Scanning files", "Analyzing", polling; `done` → counts, findings, signals, recommendations (empty state "No automations found" when there are none); `done` with `errorCode = AI_DISABLED` → counts, findings, and signals as usual, and in place of recommendations the plain notice "AI analysis is not enabled yet. Security findings and detected signals are shown above. Recommendations will appear here once AI analysis is turned on." (no error styling, no button); `rejected` → the validation reason, no findings or recommendations; `failed` → error state with a Retry (Analyze) button and the message per `errorCode`: `GITHUB_ACCESS_LOST` "Flow Motion can no longer read this repository. Reconnect GitHub and try again."; `BRANCH_NOT_FOUND` "The branch <branch> no longer exists on GitHub. Add the repository again and choose another branch." (no Retry button, since re-analyzing would fail the same way; link "Back to dashboard"); `MODEL_OUTPUT_INVALID` "The AI returned an answer we could not use. Your security findings are saved below. Try analyzing again." (findings and signals still shown); `JOB_EXPIRED` (Phase 2 review fixes, D-29) "This analysis stopped making progress and was cancelled. Try again." (Retry shown); `AI_UNAVAILABLE` (Phase 2c, D-35) "The AI service did not respond. Your security findings and detected signals are saved below. Try again later." (Retry shown; never names the provider); `INTERNAL` or anything else "Something went wrong during analysis. Try again." On every `failed` analysis whose `progress` is at least 70 (`detect` finished), the saved findings and signals are shown below the message (R2-4).
- Recommendation `new` → card with "Generate flow" (or "Try again" when `flowId` is set); `selected` → "Generating" with "View progress"; `generated` → "Flow ready" with "Open flow" (exact copy under "Card action area").
- Flow `generating` → skeleton canvas with polling; `ready` → canvas, inspector, export panel (test panel from Phase 4); `failed` → error state with the message per `errorCode` and "Back to analysis" (exact copy under "Flow page").
- Test run `level = valid` → badge "Valid" (plus the failing cases if `passed = false`); `level = simulated` → badge "Simulated" with the required wording from `testing.md`.
- `DAILY_CAP_REACHED` → plain notice "Daily limit reached (10 analyses per day). It resets at 00:00 UTC." (for generation: "30 flows per day"); `PROJECT_STALE_ANALYSIS` → dialog with "Generate anyway" and "Re-analyze" (exact copy under "Card action area"); `RATE_LIMITED` → "Too many requests, try again in a minute".

## Accessibility
Visible focus rings (accent), full keyboard navigation including the canvas where possible, labels on all form fields (react-hook-form + Zod messages), sufficient contrast, reduced motion support, semantic headings.

## Tone
Direct and honest. Never overpromise: say "Simulated with mock data", not "guaranteed to work".
